The baseline implementation must run entirely within the main backend and be deterministic. FlashRank can be added as an adapter if the team can operate its Python dependency reliably; do not let a failed model call break the feed. If using a separate Python process/service for FlashRank, treat it as an optional internal component, set a strict timeout, and fall back to baseline ranking. The MVP does not require a custom model or a vector database. 4. Information Architecture and Permissions 4.1 Institution hierarchy Institution ΓåÆ Programme ΓåÆ Department ΓåÆ Batch/Section ΓåÆ Group. Implement the hierarchy using stable IDs and parent references rather than encoding hierarchy into names. A group may have a parent group; the hierarchy is for navigation and policy inheritance only where explicitly defined. A person has one global account and may have multiple affiliations and memberships. Students normally have one primary institution in the MVP; alumni can have multiple institution affiliations. Do not duplicate a person record to represent a second institution. 4.2 Three separate permission dimensions Dimension Example rule Must not imply Profile visibility A profile can be public, institution-visible or restricted. Permission to message. Personal messaging Only accepted connections may start or continue private messaging. Group membership or posting permission. Group access and posting A group can be public, request-to-join or private; posting can be limited to members/moderators. A personal connection. 4.3 Roles and moderation Institution administrators define roles and assign them only within their authorized scope. Group supervisors can approve or decline access requests and moderate group content. Record who performed each sensitive action. Provide a higher-level escalation route; where the complaint concerns a senior administrator, offer an independent route that does not require that administrator to review their own case. Blocking prevents direct interaction and should remove or suppress the blocked person's content from relevant personal surfaces according to policy, but it must not silently remove either person from a shared institution/group membership. Group moderators may still need to handle reports within the group. 4.4 Broadcasting Human-readable audience handles such as institution/role/group labels may help administrators choose a recipient set. They are not credentials. Resolve recipients from database IDs and verify the sender's role and scope on every broadcast request. Never authorize a broadcast because a caller knows or supplies a prefix, code or opaque token. 5. MongoDB Data Model Use ObjectId references for identity and relationships, schema validation at the API boundary, and indexes for frequent access paths. Embed small, bounded data that is always read with its parent; use separate collections for growing or independently permissioned relationships such as memberships, messages and interaction events.
